The Vault by TGI Sport: Multi-Tenant Digital Asset Platform

TypeScript · NestJS · PostgreSQL (RDS) · TypeORM · Redis · FFmpeg · S3 · SQS · Lambda · ECS

Problem
Sports media and advertising teams across multiple leagues share one platform for their media. Every ingested file has to be processed, from small images to very large videos, with strict tenant isolation.
Approach
I designed and built a generic FFmpeg transcoding service for video, image and arbitrary FFmpeg-argument jobs, fed through Amazon SQS, plus REST APIs for async file processing and bulk multipart S3 uploads.
Key decisions
  • Size-based routing: jobs go to Lambda functions with different memory and timeout sizes by file size, and files that would exceed Lambda's maximum runtime run as ECS tasks on EC2.
  • Content-hash deduplication: a duplicate upload references the original S3 object through an originalFileId but still behaves as a distinct file in the app.
Impact
  • A backfill job hashed existing files and removed ~12 TB of duplicate data, about 20% of storage across all tenants.
  • Prototyped an in-house ExifTool replacement for a third-party metadata SaaS: 100% parity on critical fields across 8 media formats and up to 76x faster extraction (~29 s to 381 ms).

Client code is private.

LLM Tic-Tac-Toe Tournament

TypeScript · Node.js · Express.js · WebSockets · Vercel AI SDK · Zod

Problem
Compare how LLMs from different providers play a constrained game, live, without one misbehaving model breaking the run.
Approach
A knockout tournament engine pits OpenAI, Anthropic, Google, Groq and Mistral models against each other and streams every move to the browser over WebSockets.
Key decisions
  • Provider-agnostic LLM layer: every model returns a Zod-validated { row, col } move through the AI SDK's structured output, so adding a provider is configuration, not new game logic.
  • Defensive game loop: illegal or malformed moves are retried up to 3 times, then the player forfeits; drawn games are replayed with sides swapped.

LetItTap: Android Phone Agent

Kotlin · Android Accessibility Service · Claude API · Gemini API · LLM tool calling

Problem
Everyday phone jobs, like filling a form, setting an alarm or messaging someone, take a dozen taps in the same few apps.
Approach
An Android app with a floating bubble: say or type a task, and an LLM agent operates the phone, opening apps, tapping and typing while you watch.
Key decisions
  • Screen as text, not screenshots: the accessibility tree becomes a numbered list of elements, and the model answers with one tool call per turn (tap, type, scroll, open app, done), capped at 20 steps.
  • Guardrails in the agent loop: it refuses to pay, delete or enter passwords, one tap on the bubble stops it, and there is no backend, so the phone talks to Claude or Gemini directly.

AI Email Classifier

Python (scripting) · Laya decision model · Gmail API · OAuth 2.0 · Docker

Problem
Sort a busy Gmail inbox automatically without sending email content to a third-party AI service.
Approach
A local tool that labels Gmail with Laya, an open-weight decision model running on-device. Classified 8,000+ emails into 12 categories such as Career, Finance, Security and Suspicious.
Key decisions
  • Deterministic SPF, DKIM and DMARC checks run before the model, so phishing detection does not depend on model confidence.
  • Low-confidence emails get an Unsure label instead of a guess, and the tool only adds labels: it never archives, deletes or sends mail.

Usage HUD for Claude

JavaScript · Chrome Extensions (Manifest V3) · Service Workers

Problem
Claude's 5-hour and weekly usage limits are only visible deep in the settings page.
Approach
An open-source Chrome extension that shows both limits in the toolbar badge and a popup, from any tab.
Key decisions
  • A service worker refreshes on chrome.alarms and caches in chrome.storage, so the popup opens instantly.
  • Least-privilege permissions: storage, alarms and the claude.ai host only, with no content script.
