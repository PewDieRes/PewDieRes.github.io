Client project at Coditas · in production

The Vault by TGI Sport

Multi-tenant digital asset platform

TypeScript · NestJS · PostgreSQL (RDS) · TypeORM · Redis · FFmpeg · S3 · SQS · Lambda · ECS · ExcelJS · PDFKit

Problem
Sports media and advertising teams across multiple leagues share one platform for their media. Every ingested file, from small images to very large videos, has to be processed while each tenant stays strictly isolated.
Approach
I built backend features across the platform: tenant-level access control, REST APIs for bulk multipart uploads and async file processing, a generic FFmpeg transcoding service, and Excel and PDF features on Lambda.
Key decisions
  • Route by file size. SQS jobs go to Lambda functions with different memory and timeout sizes, and files that would exceed Lambda's maximum runtime run as ECS tasks on EC2.
  • Deduplicate by content hash. A duplicate upload points at the original S3 object through an originalFileId but still behaves as its own file in the app.
Impact
  • A backfill job removed ~12 TB of duplicate data, 20% of 60 TB across all tenants.
  • An in-house ExifTool prototype matched a third-party metadata SaaS on critical fields across 8 media formats, up to 76× faster.

Client code is private.

Personal · open source

LLM Tic-Tac-Toe Tournament

TypeScript · Node.js · Express.js · WebSockets · Vercel AI SDK · Zod

Problem
Compare how LLMs from different providers play a constrained game, live, without one misbehaving model breaking the run.
Approach
A knockout tournament engine pits OpenAI, Anthropic, Google, Groq and Mistral models against each other and streams every move to the browser over WebSockets.
Key decisions
  • One provider-agnostic layer. Every model returns a Zod-validated { row, col } through the AI SDK's structured output, so adding a provider is configuration, not new game logic.
  • A loop that can't be stalled. Illegal or malformed moves are retried up to 3 times before a forfeit, and drawn games are replayed with sides swapped.
